Automation Studio 使用說明

              
依 2.2.0 版介面整理：從專案與錄製、流程編輯、保存頁面 PDF，到測試、批次匯入匯出與發布。下方操作細節可按標題展開。

1建立專案輸入專案名稱與入口網址

主要操作說明
依功能頁面快速找到正確操作方式。

              

                
網站與工作站
設定入口網址、允許網域及瀏覽器模式，再儲存專案設定。登入、跳轉或下載若使用其他網域，也要加入允許清單；子網域可明確使用 *.example.com。
管理瀏覽器、CDP 與背景模式
管理瀏覽器：可選隨附 Chromium 或本機 Google Chrome；保存瀏覽器 Profile 可保留本機登入狀態，清除登入狀態會重設專案的登入資料。
背景模式（無頭模式／headless）：可用於管理瀏覽器的流程執行。錄製仍會顯示瀏覽器；需要人工登入、MFA 或驗證碼的流程請使用可見瀏覽器。
Chrome CDP 接管：連線至本機 Chrome 的偵錯端點，只允許 localhost、127.0.0.1 或 ::1。可設定端點無法連線時自動啟動 Chrome；背景模式不適用，流程結束後不會關閉使用者的 Chrome。
Stealth：依專案選擇啟用，適用於管理瀏覽器的錄製、執行及匯出 TypeScript；CDP 接管不適用，也不保證通過網站驗證。
錄製操作與 Frame／上傳
啟動錄製後在瀏覽器實際操作，事件會即時顯示於工作站清單；確認事件後加入流程步驟，完成後停止錄製。Enter、Tab 及組合按鍵會記錄，密碼欄位的值不保存。
子 Frame 操作會保留 Frame 路徑。重新執行找不到元件時，檢查步驟的 Frame 設定與跨 Frame 搜尋。可用「選取驗證元素」建立可見、文字或欄位值驗證。
上傳事件只保存檔名，加入流程後須補填完整本機路徑並啟用步驟；多個檔案一行一個。

                
自動化設計器
階層清單及視覺畫布中，單擊只選取步驟，雙擊開啟右側步驟設定面板（不遮擋背景畫布，可邊對照流程邊編輯）。修改後套用步驟，並儲存專案。
排序、收折與全螢幕
拖曳排序：在階層清單按住整張步驟卡片片刻後拖曳；放到目標卡上緣會插入前方，中央會交換位置，下緣會插入後方。排序限同一層級及同一分支，父步驟的子流程會一併保留；也可用上移／下移按鈕。
條件分支：True／False 分支可各自收折，標題顯示步驟數。視覺畫布按「全螢幕」放大檢視，按 Esc 或退出按鈕返回。
動作元件：依功能分為五大類別並支援關鍵字即時篩選；預設收折，可手動展開或收合，滑鼠連續停留約 0.8 秒會暫時顯示完整清單，短暫經過不會展開。
執行資訊：下方預設收折，執行時也不會自動展開。需要除錯時再查看日誌、Console、Network、Popup／Download 與變數；這些是目前執行的資訊，不是選取步驟的設定。
選取元件與等待、定期重新整理
檢查 selector 與 Frame 路徑，重複元件可使用 first／last／nth。動態頁面優先加入「等待顯示」、等待網址或 Network Idle，避免只靠固定秒數。
定期重新整理：「等待清單新資料」或「等待第一筆新資料」步驟中可勾選啟用，間隔 5～600 秒（預設 10 秒）。未找到符合條件的新資料時重新整理目前分頁；找到了立即停止，並受該步驟逾時（ms）限制。與「擷取清單快照」搭配時，重新整理不會重建既有基準，適合 Webmail 需手動刷新才能看到新信的情況。
擷取網頁資料與保存彙整文件（Word／JSON／Excel）
在動作元件新增「擷取網頁資料」，設定資料集合名稱，例如 records。單頁模式可逐欄設定名稱、CSS 定位、文字／HTML／屬性及必填；清單模式先指定每個重複項目的 CSS，欄位定位以該項目為範圍。表格模式指定 table 的 CSS，自動讀取標題及資料列。
先以等待步驟確認內容已載入。勾選追加後，翻頁或開啟下一個網址再次擷取，即可累積至同一集合；取消追加會取代資料。單次上限可設 1～5000 筆，集合最多 50,000 筆。可附加 _sourceUrl 與 _capturedAt，時間以含時區的 ISO 格式保存。
新增「保存彙整文件」，填入相同集合名稱，選擇 Word（.docx）、JSON（.json）或 Excel（.xlsx），設定檔名、欄位順序及標題。Word 可用表格或逐筆段落，Excel 可設定工作表名稱；欄位順序留空則輸出全部。Excel 以文字保留前導零及網頁內容，單一儲存格超過 32,767 字元時會提示改存 Word 或 JSON。
文件保存至「系統設定 → 預設下載路徑」，並出現在執行紀錄。每次完整執行使用獨立集合；從中段執行不會自動載入前次集合，請先準備擷取步驟。匯出的獨立 TypeScript 使用 DOWNLOAD_DIR，未指定時保存至 downloads。
保存頁面 PDF
新增原生「保存頁面 PDF」動作，將目前頁面列印為 PDF，無須 selector。Studio 執行時存至「系統設定 → 預設下載路徑」，同名檔案會另編名稱避免覆蓋。
檔名：可自訂，例如 台灣銀行決算_品質檢測結果_20261007_103000.pdf，也可使用 {{參數}}。自動使用本機時間命名預設啟用，時間取自執行電腦。
版面：A4／Letter、直向／橫向、是否包含背景色、上／右／下／左邊界（各 0–50 mm），以及 10%–200% 縮放比例。
頁首／頁尾：啟用輸出後填入 HTML 範本，並預留足夠的上下邊界。只填範本但未啟用，不會輸出頁首／頁尾。
完整頁面：預設啟用，內容會依紙張尺寸分頁，可能產生多頁 PDF。網站的列印樣式也會影響輸出，請檢查實際 PDF 的版面。
設定後套用步驟再測試，執行日誌會顯示實際採用的紙張、方向、縮放與頁首／頁尾狀態。此功能與下載網站提供的 PDF 檔案不同。

                
參數與資料
以 {{year}} 等參數代換網址、selector 或填值。參數 Key 須以英文字母或底線開頭，後接英數字或底線，且不可重複。
預設值、相依選項與敏感參數
依資料設定型別、必填、預設值與固定選項；父子相依下拉選單及批次任務使用同一份定義。新增批次列會帶入非敏感參數的預設值；執行前仍須確認必填資料與相依選項。
密碼等資料請使用 secret 型別或標記為敏感。發布會清空這些參數的預設值，但一般文字與直接寫在步驟中的值仍會保留，請在發布前檢查。

                
測試與 Debug
先選擇適合的執行範圍驗證流程；執行失敗時可用內建 AI 分析，或下載遮罩後的診斷包提供外部 AI／支援人員。

巢狀流程：直接從條件／迴圈內子步驟開始時，不會重新執行外層條件判斷或之前的迴圈次數；若要完整語意，請選取父步驟。

                      

                    

                    

                      執行失敗後：AI 分析與失敗診斷包
                      

                        
AI 分析失敗原因：失敗後整理錯誤、失敗步驟、selector、Console／Network／Popup／Download 與頁面摘要，交由目前 AI Provider 分析根因與修正建議。

                        
候選步驟修正：AI 可建議 timeout、等待條件、iframe、matchMode、下載模式或 selector；新的 selector 必須來自失敗頁面實際觀察證據。確認後再按「套用候選修正」，並先用「只執行此步驟」重測。

                        
下載失敗診斷包：輸出遮罩後 ZIP，包含執行摘要、失敗步驟、近期事件、頁面文字／元素摘要、selector 候選與失敗截圖，方便外部 AI 或支援人員分析。

                        
    
                          
  1. 執行失敗後先按「AI 分析失敗原因」。
    2. 
                          
  2. 確認候選修正合理後套用，再單步重測。
    3. 
                          
  3. 若仍無法判斷，再下載診斷包 ZIP；提供外部 AI 前請自行檢查內容。
    4. 
                        

                        
機敏資料：診斷包會遮罩 Cookie、Authorization、API Key、密碼、URL query value 與流程變數值，但截圖或頁面可見文字仍可能包含業務資訊，分享前請依組織規範檢查。

                      

                    

                  

                

                
批次任務
每列代表一組執行參數。「編號／執行」欄的勾選決定是否執行，欄位標題的勾選框可全選或全取消所有列，包括未捲動到的列。左側資料列選取用於複製、批次修改與刪除。
編輯與匯入／匯出批次內容
雙擊或按 Enter 編輯儲存格，方向鍵／Tab 移動，Ctrl／Cmd+V 可貼上 Excel 範圍。拖曳欄名可排序，拖曳分隔線調整寬度。
匯出批次內容：支援 JSON 及 UTF-8 CSV，匯出整份清單（包含未勾選列），敏感參數不匯出。JSON 保存型別與執行勾選，適合備份；CSV 欄名使用參數 Key，__studio_enabled 為 true／false，匯入時省略則預設啟用。Excel 編輯代碼欄請使用文字格式保留前導零。
匯入批次內容：先檢查資料，再選「加入目前清單」或「取代目前清單」。欄位、型別或相依選項錯誤時不變更原清單；未填完的必填內容可作為草稿匯入，執行前仍須補齊。每次上限 5 MB、10,000 筆。
進階設定與 1–3 筆並行
進階設定預設收折，按標題展開後可調整重試、播放方式、最小步驟間隔、截圖及同時執行數，變更會自動儲存。
管理瀏覽器：預設 1 筆依序執行，可改為 2 或 3。並行批次各用獨立瀏覽器工作站；首次可能需要各自登入，之後同一工作站沿用批次工作階段及已完成的人工登入檢查點。執行紀錄標示工作站編號，暫停時完成操作後按繼續。
Chrome CDP：共用既有瀏覽器，固定 1 筆依序執行。網站若限制同帳號多重登入，管理模式也請選 1；登入逾期或工作階段重建時可能需重新驗證。系統最多同時執行 3 筆，超過的任務等待排程。

                
執行紀錄
查看所有專案的任務狀態、開始時間、執行模式、步驟進度及失敗原因。可依專案或狀態篩選，按「重新整理」更新清單。
展開詳情、下載成果與失敗診斷包
點選紀錄列或「展開詳情」，即可在該筆紀錄下方查看執行結果；再次點選可收合。已產生的成果可按「開啟檔案」檢視，或按「開啟資料夾」查看所在位置。
失敗任務可按「下載失敗診斷包 ZIP」。若 Debug 資料已到期清除，診斷內容可能不完整或無法取得；需要分析時請先下載保留。
選取與刪除紀錄
勾選個別紀錄，或使用「全選目前結果」及「取消全選」，再按「刪除選取紀錄」。也可使用「刪除目前篩選結果」、「清除完成紀錄」，或個別紀錄的「刪除此紀錄」。
執行中、等待中與等待人工操作的紀錄受到保護，不能刪除。刪除會移除該次執行紀錄與 Debug 資料，已下載的成果檔案會保留。保留天數與到期清理請到「系統設定」調整。

                
發布與版本
測試完整流程後再發布。可攜工作流程 ZIP 可匯入另一台 Automation Studio；TypeScript 可獨立執行；SKILL.md 提供使用指引。瀏覽器 Profile、Cookie 與登入工作階段不會攜出，敏感參數預設值會清空；一般文字或步驟內直接填入的資料仍會保留。
系統版本與專案版本怎麼區分？
Automation Studio 系統版本採 MAJOR.MINOR.PATCH；第二、第三段限定 0–9，超過 9 向前進位，例如 1.9.0 → 2.0.0、2.0.9 → 2.2.0。新增功能升 MINOR，修正升 PATCH。目前系統版本為 2.2.0。專案版本號則屬於個別工作流程，可由使用者自行管理，兩者互不影響。進位至新主版不代表流程資料不相容。

                
系統設定與開發者功能
系統設定可調整外觀、預設下載路徑、紀錄保留及支援信箱；AI Provider 可展開後設定。服務啟動就緒後固定自動開啟介面，沒有取消選項，與流程背景模式分開管理。
紀錄保留、Debug 清理與工作流程原始碼
Debug 與執行紀錄的保留天數分開設定；僅失敗保留模式會移除成功任務的 Debug。可手動清理過期資料，刪除執行紀錄不會刪除已下載的檔案。
「開發者功能」中的 AI 流程助理可探索頁面並建立可編輯草稿，請檢查修改後再送出及測試；AI 呼叫依 Provider 設定可能需要網路。「工作流程原始碼」提供 JSON 編輯，按「套用 JSON」檢查基本結構，不可更換目前專案 ID；修改後仍須實際測試。

              

            


            

              
常用判斷原則
遇到流程不穩定時，先檢查這些項目。

              
    
                
  1. 元件找不到：確認 selector 是否使用動態 class／id，優先使用文字、label、role 或穩定屬性。
    2. 
                
  2. 頁面尚未載入：用等待顯示／等待網址／Network Idle 取代過短固定延遲。
    3. 
                
  3. 登入後卡住：將登入設為人工操作，完成條件使用按鈕或穩定的登入後網址。
    4. 
                
  4. PDF 版面不符：確認使用「保存頁面 PDF」、套用後的縮放與頁首／頁尾設定、邊界及網站列印樣式；網站 PDF 下載則檢查下載步驟。
    5. 
                
  5. 批次登入問題：檢查各工作站是否完成登入、是否重複關閉分頁，以及網站是否限制多重登入；必要時改為 1 筆依序執行。
    6. 
              

            

          


          

            
常見問題 FAQ
點擊問題即可展開答案。

            

              
為什麼錄製成功，但重新執行時找不到按鈕？
通常是 selector 過度依賴動態 class、暫時 id 或頁面尚未完成載入。建議在自動化設計器改用穩定文字／role／label，並在前一步加入適當等待。

              
帳號、密碼、Cookie 會被匯出嗎？
匯出會清空標記為敏感或 secret 型別的參數預設值，且不包含瀏覽器 Profile、Cookie 或登入工作階段。一般參數與直接寫在步驟中的文字仍會保留，因此帳密請改用敏感參數，發布前再檢查內容。批次內容匯出也會省略敏感參數。

              
CDP 模式與 Automation Studio 管理瀏覽器有什麼差別？
管理模式由系統建立專用瀏覽器與 Profile；CDP 模式接管本機已開啟的 Chrome，適合需要沿用既有登入狀態的網站。流程結束時只解除控制，不會主動關閉外部 Chrome。

              
為什麼下載 PDF 時只看到預覽頁？
Chrome 可能使用內建 PDF Viewer。可在網站與工作站啟用「PDF 直接下載，不開啟預覽」，或將流程步驟改成下載並使用 auto/click 模式。

              
批次任務中需要每筆都重新登入嗎？
同一批次工作站可沿用瀏覽器工作階段及已完成的人工登入檢查點。2–3 筆並行使用各自獨立的工作站，首次可能需分別登入；網站登出、登入逾期或工作階段重建時仍需重新驗證。

              
如何判斷錯誤發生在哪裡？
先看「測試與 Debug」的執行錯誤與步驟結果，再依情況查看 Console、Network、Popup/Download 或變數。歷史任務也可在「執行紀錄」展開詳情查看。

              
「只執行此步驟」與「從此步驟執行」有什麼差別？
「只執行此步驟」只測目前選取的單一步驟；「從此步驟執行」會從選取步驟開始繼續執行後續流程。兩者都不會自動重跑選取步驟之前的登入、導頁、搜尋或變數建立，因此使用前要先準備好正確的瀏覽器與資料狀態。

              
可以把一份流程搬到另一台電腦嗎？
可以，使用「發布與版本」輸出可攜工作流程 ZIP，再由另一台 Automation Studio 匯入。登入狀態與本機 Profile 不會一起移轉，敏感參數需在目的端補填；步驟內的本機檔案路徑也要重新確認。

              
如何使用「發布與版本」輸出的 TypeScript 專案獨立執行？需要哪些 Node.js 套件？
                
發布時勾選 TypeScript 後，匯出的 typescript-project 資料夾本身就是可獨立執行的 Playwright 專案，不需要再開啟 Automation Studio。基本相依套件為 playwright；若管理瀏覽器啟用 Stealth，還會包含 playwright-extra 與 puppeteer-extra-plugin-stealth。依匯出的 package.json 安裝即可，不需要另外安裝 typescript 或 ts-node，因為 start.bat 會使用 Node.js 的 --experimental-strip-types 直接執行 src/run.ts。

                
    
                  
  1. 準備 Node.js：需要支援 --experimental-strip-types 的 Node.js（Node.js 22.6 以上），也須符合匯出套件的執行環境要求。使用公司核准的 Node.js 版本。安裝後在命令提示字元執行 node -v 與 npm -v 確認可用。
    2. 
                  
  2. 取得 Node.js：可由 Node.js 官方網站下載 Windows 安裝版；公司電腦若無管理者權限，可使用資訊單位提供的軟體中心，或下載官方 Windows ZIP 版解壓縮後使用，並將該資料夾加入目前工作階段的 PATH。
    3. 
                  
  3. 安裝專案套件：解壓縮發布檔後進入 typescript-project 資料夾，執行 npm install。npm 會依 package.json 安裝 Playwright 及啟用 Stealth 時的額外套件。
    4. 
                  
  4. 準備瀏覽器：若流程使用 Playwright 隨附 Chromium，再執行 npx playwright install chromium。若專案設定使用本機 Chrome，且 Chrome 已安裝，通常不需要下載 Chromium。
    5. 
                  
  5. 設定參數：若發布時勾選範例，將 parameters.example.json 複製成根目錄的 parameters.json 後填值；沒有範例時自行建立 JSON 物件，欄位名稱須對應參數 Key。未提供的參數沿用非敏感預設值，敏感參數需自行補填。
    6. 
                  
  6. 執行：Windows 可直接執行 start.bat；也可在命令列執行 npm start。流程若包含人工登入、MFA 或驗證碼，請使用可見瀏覽器並人工完成；匯出的命令列流程若以按鈕確認人工步驟，依終端提示按 Enter 繼續。
    7. 
                

                
下載位置：匯出的專案不會自動讀取 Studio 系統設定。「保存頁面 PDF」使用 DOWNLOAD_DIR 環境變數，未設定時存入執行目錄的 downloads。

                
離線／內網環境：如果執行電腦無法連到 npm 或 Playwright 下載站，應先在可連網環境完成 npm install 與需要的瀏覽器安裝，再依單位軟體供應政策準備離線套件；不要為了繞過公司憑證而關閉 TLS 驗證。

              

              
啟動時顯示「正在載入介面」或載入失敗怎麼辦？
啟動會先準備新版介面與工作空間資料，完成後才顯示功能頁面。超過 30 秒會提示可繼續等候或重新整理；若顯示載入失敗，確認服務仍在執行且程式檔案完整後按「重新整理」。不會自動切回舊版畫面。

              
遇到無法自行排除的問題怎麼辦？
使用左側「回報問題」，填寫重現步驟與實際結果。系統會開啟預設郵件程式中的草稿，需自行確認並寄送；沒有郵件程式時可複製回報內容。必要時另附經檢查的畫面截圖。
